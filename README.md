# 工作提醒器

适用于 Windows 10 / 11 的本地桌面工具。双击 `WorkReminder.exe` 或桌面上的“工作提醒器”快捷方式即可打开。关闭主窗口后程序仍在系统托盘运行；通过左下角退出按钮或托盘菜单退出才会停止提醒。

## 日常工作

1. 在左侧选择项目。可新建项目，并填写负责人、工作目标、衡量标准、计划完成日期和风险与所需支持。“全部项目”汇总展示；在此视图新建事项时，可在右侧选择所属项目，默认“未归类”。
2. 在右侧填写工作事项、提醒时间和可选的计划完成日期，点击“保存提醒”。提醒到点弹窗、延后或直接关闭都不会把事项标为完成；直接关闭弹窗默认延后 10 分钟。
3. 工作做完后勾选该行的“完成”复选框，或在弹窗点击“本项已完成”。单次事项会保留为“已完成，待安排下一步”，并停止当前步骤的提醒。
4. 选中已完成的末尾事项，可以“添加下一步”，填写新事项及独立提醒时间；也可以明确点击“没有后续，闭环”。不填写下一步不会自动闭环。已闭环事项在归档前仍能重新添加下一步。
5. 每天、周一至周五、每周重复事项完成时会保留本次完成记录，并自动生成下一次。未编辑的自动下一次可选中后点击“结束重复并闭环”。已编辑或已推进的事项需要按普通步骤处理。
6. 选中事项可在右侧查看整条工作链的顺序、备注、提醒与完成时间。移动项目会移动该链的全部当前步骤。只有没有当前或归档事项引用的空项目可删除。

“全部待办”显示未完成事项与待安排下一步的末尾事项；“待安排下一步”集中显示尚未决定后续的工作；“已完成”显示当前数据中的所有已完成步骤。重复事项的工作日规则只排除周六、周日，不处理法定节假日和调休。

## PBC 汇报

在左侧选中项目后点击“导出 PBC”，导出该项目及其事项；选择“全部项目”会按项目分组导出。可在“导出设置”选择本周、本月或自定义日期。首次导出选择输出文件夹，此后沿用该目录和周期模式。本周、本月的具体日期每次导出时重新计算。

每次导出创建一个独立目录，包含可打印的 `PBC汇报.html` 和可编辑的 `PBC汇报.md`。汇报包含目标、衡量标准、本期成果、风险与支持、下一步计划、当前工作状态、闭环记录和事项明细，并读取已有归档。完成数量仅是工作统计，不会自动计算绩效得分。成果和依据未填写时会明确标注；历史时间未知的记录不计入本期完成数。HTML 可在浏览器中打印为 PDF。程序不会自动发送汇报文件。

## 归档与备份

当前数据位于 `%LOCALAPPDATA%\WorkReminder\tasks.json`；每次保存会生成上一个版本的 `tasks.json.bak`。旧版数据首次用新版程序打开时，先保存 `tasks.json.pre-migration-*` 完整快照，再迁移到版本 2。旧事项归入“未归类”；旧已完成事项为“待安排下一步”，不会推断闭环时间。

如程序目录有 `data-location.txt`，其中的绝对文件路径优先于上述默认位置，桌面程序、MCP、安装脚本和归档脚本均使用它。Windows 商店版应用可能重定向 AppData；接入时应核对桌面正在使用的数据，将完整数据和归档备份后放在双方都可访问的目录（例如用户目录下的 `WorkReminderData`），再配置同一个 `tasks.json` 路径。不要把不同来源的旧副本直接覆盖到当前数据上。此机器专属配置已被 Git 忽略。

需要清理已闭环的工作链时，先正常退出程序，再在本目录运行：

```powershell
pwsh -File .\archive-completed.ps1
```

脚本仅将**明确闭环的完整工作链**移入同一数据目录的 `archive.json`，保留所有步骤及项目名称快照；仅完成但尚未明确闭环的事项不会归档。归档前会生成 `tasks.pre-archive-*` 完整快照。旧归档继续保留，PBC 汇报仍可读取。若数据损坏，程序或脚本会报错并保留原文件；请先另存损坏文件，再考虑从 `.bak` 或快照恢复。

开机启动可在左下角开启，默认关闭。数据保存在本机，不提供跨设备同步。电脑关机、休眠或程序退出期间不能弹窗；恢复运行后会提醒仍未完成的到期事项。

## Codex 双向接入

在主窗口选择项目后点击“Codex 助手”，即可用本机 Codex 当前登录和模型对话；选择“全部项目”时可管理多个项目。助手会显示连接状态和项目范围，支持连续追问、停止、重新连接、复制和保存草稿。切换项目会关闭原助手；关闭助手后本次会话结束，不保存聊天历史。

可直接输入：

- “帮我把这个项目的下周工作拆成待办草稿，先不要保存。”
- “在当前项目新建‘提交设计方案’，2026 年 10 月 23 日下午 3 点提醒我。”
- “‘提交设计方案’已经完成，下一步是跟进审批，10 月 26 日上午 10 点提醒。”
- “这项工作没有后续了，请闭环。”
- “根据本月真实记录整理 PBC 汇报草稿，并指出还缺哪些成果依据。”

AI 建议先作为草稿；只有你明确要求创建、更新、完成或闭环时才执行对应操作。提醒到期仍不等于完成，完成也不自动闭环。项目范围由本机操作服务校验；助手不能越过当前项目管理其他项目。界面有未保存修改时，外部更新会保留输入，并在过期保存时提示重新选择事项。

安装 Codex CLI 并完成登录后，在本目录运行以下命令，把同一份待办接入本机 Codex 聊天：

```powershell
pwsh -File .\install-codex.ps1
```

若 `codex` 命令指向 npm 的 `.ps1` 或 `.cmd` 包装脚本，请用 `-CodexPath "C:\实际安装目录\codex.exe"` 指定原生可执行文件。安装器会在修改配置前拒绝包装脚本。

安装脚本备份现有 Codex 配置，注册 `work_reminder` MCP 服务，并在本机 `codex-path.txt` 中记录 Codex CLI 的绝对路径，使桌面快捷方式启动助手时也能找到 CLI。该机器专属路径不提交到 Git；CLI 更新并移除旧路径后，可重新运行安装脚本刷新。**重新启动 Codex 或重载 MCP 服务**后，可以在聊天中说“用工作提醒器查询今天待办”，或者明确要求新建项目、修改提醒、记录完成、添加下一步、闭环和导出 PBC。程序未运行时，工具会自动后台启动提醒器。应用内助手仅启用本提醒器工具，不继承其他 MCP、插件或 shell 执行能力；你原有 Codex 配置和其他聊天工具不受影响。

卸载连接：`pwsh -File .\install-codex.ps1 -Uninstall`。这只移除 MCP 注册，保留项目、待办和手动提醒功能。

Codex 对话会按你当前的 Codex 服务配置联网，将请求所需的项目与事项内容发送给模型；使用和计费沿用现有配置。手动管理与提醒仍可离线使用。此版本已在 Windows、本机 Codex CLI `0.163.0-alpha.10.2` 上完成真实模型查询与创建验证；不兼容的 CLI 或登录失效会在助手状态中显示。

“停止”会尝试中断当前回答，但不会撤销已经提交的待办修改。连接中断后先查询结果；工具使用持久化请求编号避免重复写入，超时后应通过 `request_status` 查询原编号，不要换编号重复创建。MCP 导出的 HTML 和 Markdown 位于实际数据目录下的 `exports`，程序不会自动发送给他人。

## 开发与验证

源码使用 C#、WPF、.NET Framework 4 和 PowerShell，编译器来自 Windows 系统目录，无 NuGet 或网络依赖。测试使用隔离数据目录，不会写入正式待办。

```powershell
pwsh -File .\build.ps1
pwsh -File .\verify-ui.ps1
pwsh -File .\ArchiveTests.ps1
pwsh -File .\verify-bridge-integration.ps1
pwsh -File .\verify-system.ps1
```

`build.ps1` 编译程序和 MCP，并运行核心、报告、操作服务、管道、MCP 协议与启动、Codex 客户端测试；`verify-ui.ps1` 测试真实 WPF 窗口并将截图保存到 `verification/`；`ArchiveTests.ps1` 测试整链归档和旧归档兼容；`verify-bridge-integration.ps1` 使用独立数据验证 MCP 自动启动、真实写入、完成与闭环、导出及重连幂等；`verify-system.ps1` 验证后台运行、托盘与退出。系统测试使用独立数据文件和唤醒信号，不操作正在运行的正式实例。

开发时可用 `WorkReminder.exe --data-file <绝对路径>` 和 `WorkReminder.Mcp.exe --data-file <相同绝对路径>` 隔离数据。应用进程负责串行保存；不要让其他脚本直接并发修改 JSON。`verify-codex.ps1` 的假传输测试不联网；`CodexSmoke.cs` 是手动真实模型验收入口，须显式传入隔离数据路径，按现有 Codex 配置产生请求。
