# 工作提醒器与 Codex 双向接入设计

日期：2026-10-19

状态：已实施并完成正式部署；实现与验证记录见同日实施计划。

## 目标与第一版范围

沿用当前 Windows 桌面提醒器，为同一份项目和待办数据增加两个入口：提醒器内的 Codex 助手，以及 Codex 本地聊天可调用的工作提醒器工具。

第一版支持查询项目与待办、创建项目和待办、修改提醒时间与备注、明确标记完成、添加关联下一步、明确闭环，以及导出已有 PBC 汇报。应用内助手可把自然语言整理为待办草稿、提出下一步建议，并基于真实完成记录生成 PBC 文案草稿。

任务拆解默认生成同项目下的独立待办草稿。只有当前事项已完成时，才可将一个事项保存为它的关联下一步；不提前创建不符合现有工作链规则的未完成串联步骤。现有归档脚本继续负责整链归档，第一版不通过 AI 执行删除、批量清空或归档操作。

## 方案选择

| 方案 | 适用情况 | 取舍 |
| --- | --- | --- |
| Codex App Server + 本地 MCP（推荐） | 提醒器内连续对话，并从 Codex 聊天管理待办 | 使用官方对话协议和工具协议，支持流式输出、继续对话、取消请求；需要适配本机 Codex 版本 |
| Codex 非交互命令 + 本地 MCP | 以“拆解任务”“生成汇报”等单次按钮为主 | 应用内实现较少，但完整对话、审批事件和恢复控制较弱 |
| OpenAI API + 本地 MCP | 独立于本机 Codex 的单独 AI 产品 | 需要独立维护模型调用、工具循环、凭据及计费配置，与本次接入本机 Codex 的目标不如第一种直接 |

采用第一种；先实现两个入口共用的操作服务与 MCP，再接入应用内对话，作为同一次双向接入交付。

## 用户体验

主窗口增加“Codex 助手”入口，打开独立助手窗口，保留当前主窗口的待办编辑区。助手显示连接状态、正在使用的上下文、对话内容、操作结果和停止按钮。

默认上下文是当前选中的项目；选择“全部项目”时可跨项目查询。发送到模型的是完成当前请求所需的项目、事项和汇报记录。项目切换后开始新的项目对话，避免将上一项目的建议应用到另一项目。

示例：

- “明天下午三点提醒我跟进供应商报价”：提取具体项目、日期和时间；缺失必需信息时提问，不凭空选择项目或时刻。
- “把这个项目拆成几项工作”：显示待办草稿，用户可以编辑和选择采用。
- “这项做完了”：将明确对应的事项置为“已完成，待安排下一步”。
- “没有后续了，闭环”：对明确对应且符合条件的工作链执行闭环。
- “生成本月 PBC”：使用真实记录导出报告；AI 补充的表述作为草稿单独展示，经用户采用后才纳入报告文案。

查询和用户明确指令可直接执行；AI 自行提出的新增或变更建议先形成可审阅草稿。同名事项、相对时间含糊、项目不明确时先澄清。是否完成、是否闭环分别由用户明确表达；提醒触发和 AI 建议本身都不代表工作已完成。

## 技术结构与一致性

1. **提醒器操作服务**：提取现有项目、事项和工作链操作，调用现有 `WorkflowService`、`StateStore` 与报告模块。窗口按钮与外部工具复用同一套校验。
2. **本地通信**：提醒器作为运行期间唯一的数据写入者，通过仅限当前 Windows 用户访问的命名管道接收操作。写操作调度到窗口线程串行执行，成功保存后再返回结果并刷新界面。MCP 进程不直接改写 `tasks.json`。
3. **MCP 入口**：单独的控制台程序使用标准输入输出协议，提供项目、待办、工作链和 PBC 工具，将请求交给本地操作服务。配置使用绝对可执行文件路径，不依赖启动目录。
4. **应用内 Codex 客户端**：启动本机 `codex app-server`，使用 stdio 通信，处理初始化、账户状态、模型列表、对话、流式事件和取消。通过同一 MCP 入口访问提醒器。
5. **并发与重试**：变更带预期版本，过时的草稿或编辑被拒绝并要求刷新；写请求带请求编号，重复请求返回先前结果。操作失败不得显示为已保存，超时后先查询请求结果，避免盲目重试生成重复待办。
6. **编辑保护**：外部更新不能静默覆盖用户尚未保存的表单。保留输入并提示记录已变化，在提交时再次核对版本。

若提醒器未运行，工具入口可启动已配置的正式程序并等待连接；启动失败或数据损坏时返回明确错误。普通手动提醒与 AI 请求分别运行，AI 网络异常不阻塞本地提醒。归档脚本仍要求正常退出提醒器后执行。

## 账户、模型与数据

复用本机 Codex 支持的登录与模型配置，通过官方账户接口查询连接状态。检测到的 CLI 版本为 `0.163.0-alpha.10.2`；当前 CLI 报告使用 API Key 身份。该结果不等同于已验证模型调用成功，真实请求连通性在实施时验证，费用与可用额度以实际配置的服务和账户为准。

提醒器不读取或复制密钥到项目数据、日志或 GitHub。Codex 未安装、登录失效或模型不可用时，显示可操作的错误信息。协议结构以安装版本生成的 schema 为依据，不硬编码未经验证的最新模型名称。App Server 当前带实验性标记，适配层与业务逻辑分离，兼容性测试覆盖协议错误和进程退出。

用户数据仍保存在本机；使用 AI 时，相关请求内容会由本机 Codex 按其配置发送给模型服务。这不构成跨设备同步。第一版 Codex 聊天管理指本机 Codex 客户端，不承诺网页或另一台电脑可以访问本地提醒器。

## 错误处理与验证

- 保留提醒不等于完成、完成不自动闭环、工作链不分叉等既有回归测试。
- 使用隔离数据验证 MCP 初始化、工具发现、查询、新建、更新、完成、下一步、闭环及 PBC 导出。
- 同时测试窗口编辑与聊天修改，确认不会丢失更新；测试重复请求和过期草稿。
- 验证取消、超时、模型失败、MCP 连接中断时，不生成未确认待办，不阻塞到点提醒。
- 真实 AI 冒烟测试仅使用专门的测试项目与隔离数据，不把正式工作事项发送为测试素材。
- 安装 MCP 配置前备份，保留其他现有服务；只更新本项目对应配置。
- 更新文档和忽略规则，确认源码仓库不包含账户凭据、真实待办或本地助手对话记录。
